# Why no front end

A procedure desk is a record of who needs to do what, in which order, and with what evidence. A coding agent can read that record, execute the operator's instruction and hand back the answer. The database remains the source of truth.

This version has no mobile task app, offline synchronisation, drag and drop designer, guest portal or background scheduler. It does not send reminders or execute work inside another service. Shared access and integrations need to be built and tested for your environment. Keep any existing controls until that work is complete.

Read-only HTML gives the team a handover list and the procedure's execution record. It is a point-in-time report, not a live service. /new-view adds another report. /customise changes a field, rule or workflow through a migration and the command recipes. Enterprise DNA can build shared screens, identity controls and connections around these records as part of your version.
